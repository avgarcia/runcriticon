# Planes de formación

Itinerarios de aprendizaje para el equipo de Runcriticon. Cada plan está **anclado al proyecto**: lo que se estudia se conecta con decisiones reales (los ADR) y con el stack que se va a construir, para que la formación no sea abstracta.

## Planes disponibles

| Plan | Para qué | A quién le sirve |
|------|----------|------------------|
| [AWS](aws.md) | Operar la infraestructura del proyecto en AWS | Equipo técnico; útil también para negocio a nivel conceptual |
| [Seguridad Web/API](seguridad-web-api.md) | Construir y revisar la aplicación sin agujeros de seguridad | Equipo técnico |
| [ADRs y decisiones de arquitectura](adrs-y-decisiones-de-arquitectura.md) | Tomar y documentar decisiones de arquitectura con criterio | Todo el equipo, negocio incluido |

## Cómo usar estos planes

- No hay que completarlos antes de empezar a trabajar: son un mapa para ir aprendiendo **en paralelo** al desarrollo.
- Cada plan se organiza en **niveles/módulos** ordenados de menos a más. Cada módulo indica objetivo, temas, **conexión con Runcriticon** y recursos.
- La prioridad sugerida cuando arranque el equipo: Seguridad (transversal y crítica) → AWS (para desplegar) → ADRs (continuo).
- Los recursos citados son puntos de partida; no sustituyen la documentación oficial vigente.

> Estos planes son documentación viva: se actualizan a medida que el proyecto evoluciona y se toman nuevas decisiones.
